## Description

On error, system grants access or leaves partial state instead of deny/rollback. Mapped under A10:2025.

## Impact

Unauthorized access or corrupted transactions during fault conditions.

## Mitigation

Fail closed; rollback transactions; deny by default on errors.

## Replication Steps

1. Induce faults during security-sensitive operations.
2. Observe whether access is granted.
3. Check database state after errors.
4. Document fail-open behavior.
5. Recommend fail-closed design.
