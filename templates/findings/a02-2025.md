## Description

Security misconfiguration occurs when systems, applications, or cloud services are deployed with insecure defaults, unnecessary features, weak permissions, missing security headers, or verbose error handling. With highly configurable platforms, misconfiguration is pervasive across the stack.

## Impact

Misconfigurations can expose source code, credentials, administrative interfaces, or sensitive data. Attackers often chain low-severity misconfigurations into account takeover or data breach.

## Mitigation

Implement repeatable hardening baselines; remove unused features; change default credentials; disable directory listing; send security headers (CSP, HSTS, etc.); use centralized configuration; automate configuration compliance scanning; restrict cloud storage and IAM permissions.

## Replication Steps

1. Review HTTP response headers and TLS configuration.
2. Check for default credentials on admin consoles and middleware.
3. Test directory listing and exposed backup or debug endpoints.
4. Review cloud storage and IAM policies for public access.
5. Trigger errors and assess information disclosed.
